ALBANIA SKY · REST API · v1.0.0

Kërkim fluturimesh për KINGS NESTI

Vetëm lexim. Për bot Node.js në Render që përdor Claude. Nuk kërkohet MCP. API-ja e partnerëve është e veçantë dhe nuk ndryshohet.

1. Endpoint dhe autentikimi

POST https://albaniasky.com/api/chatbot/v1/flights/search
Content-Type: application/json
Authorization: Bearer YOUR_DEDICATED_KEY

Administratori hyn në panelin e brendshëm në të njëjtin domain, pastaj hap menaxhimin e çelësit. Nëse paneli i brendshëm përdoret te kingsmanagment.com, hapni menaxhimin në atë domain. Çelësi shfaqet vetëm kur krijohet. Në databazë ruhet vetëm hash-i. Krijimi i një çelësi të ri çaktivizon të vjetrin; butoni i çaktivizimit e revokon.

Vendoseni në Render si sekret ALBANIA_SKY_API_KEY. Mos e vendosni në GitHub, query string, frontend apo prompt-in e Claude. Claude prodhon parametrat; vetëm serveri Node shton header-in.

FushaRregulli
from / toTë detyrueshme; kode aeroportesh IATA me 3 shkronja të mëdha, p.sh. TIA, BGY. Aeroporte, jo qytete. Nuk mund të jenë të njëjta.
departure_dateE detyrueshme; YYYY-MM-DD, datë jo në të kaluarën sipas Europe/Tirane.
return_dateOpsionale; datë ≥ nisjes. Kërkon drejtimin e kundërt. Dy segmente të pavarura, jo biletë e garantuar vajtje–ardhje.
adultsNumër i plotë 1–9; default 1.
childrenNumër i plotë ≥0; default 0. Adults + children ≤9.
infantsNumër i plotë ≥0; default 0; jo më shumë se të rriturit. Nuk zënë vend.

Fushat e panjohura refuzohen, përfshirë agent_id. Agjencia caktohet nga kredenciali, jo nga boti.

5. Çfarë çmimi t'i tregojë boti klientit?

pricing.total është çmimi për të gjithë pasagjerët e kërkesës për atë segment, përfshirë taksën dhe pa shtesat opsionale. Zbatohen të njëjtat rregulla, ulje, markup, oferta të kanalit të agjentëve dhe rrumbullakim si në portalin e NESTI-t. Nuk është çmim neto administratori dhe nuk është automatikisht një çmim tjetër publik.

  • Mos shtoni përsëri markup-in apo zbritjen e NESTI-t: janë llogaritur.
  • adult_ticket / child_ticket / infant_ticket janë për person, pa taksën e veçuar.
  • tickets_total = adults × adult_ticket + children × child_ticket + infants × infant_ticket.
  • taxes_total = të gjithë pasagjerët, përfshirë foshnjat, × tax_per_passenger.
  • total = tickets_total + taxes_total. Për vajtje–ardhje mblidhen totalet e dy fluturimeve të zgjedhura; mos mblidhni të gjitha alternativat.
  • Bagazhi i regjistruar me checked_price > 0 është pagesë shtesë. null do të thotë e papërcaktuar, jo falas. Mos premtoni përmasa ose përfshirje që nuk i jep përgjigjja.
  • Orët dhe datat përdorin konventën e sistemit Europe/Tirane. Mos i interpretoni si UTC ose si orë lokale të çdo aeroporti.

6. Aksesi dhe freskia

Rezultatet respektojnë grupin dhe përjashtimet e NESTI-t, statusin Open, afatin e shitjes, bllokimin e shitjeve të jashtme dhe vendet e lira për adults + children. Ndryshimet e lejeve lexohen në kërkesën tjetër. Çmimet lexohen nga sistemi; ky endpoint nuk nxit kërkime të reja në Google. Nuk bllokon vende dhe nuk rezervon asgjë. Bëni kërkim të ri para se të konfirmoni një çmim te klienti.

outbound: [] do të thotë se nuk ka rezultate të lejuara për kërkesën; jo se të gjitha fluturimet e linjës janë anuluar. inbound: [] është normale pa datë kthimi ose kur nuk ka rezultate kthimi.

7. Gabimet dhe kufijtë

HTTPKuptimi
400INVALID_REQUEST — kontrolloni parametrat; mos riprovoni të njëjtën kërkesë.
401UNAUTHORIZED — çelës i pavlefshëm, mungon ose është revokuar.
403AGENCY_UNAVAILABLE — agjencia joaktive ose pa grup aksesi.
429RATE_LIMITED / BUSY — prisni sekondat e Retry-After.
503SEARCH_UNAVAILABLE — problem teknik; mos e paraqitni si “nuk ka fluturime”. Riprovoni më vonë.
{"error":{"code":"INVALID_REQUEST","message":"Only EUR is supported"}}

30 kërkesa/minutë për kredencial, maksimumi 2 kërkime njëkohësisht. Mbrojtja e autentikimit lejon gjithsej 300 tentativa/minutë. Kufijtë janë për proces serveri, me dritare fikse dhe rivendosen pas rinisjes. Kërkesat e autentikuara por të pavlefshme numërohen në kufi. Gabimet nga proxy ose JSON i dëmtuar mund të kenë format tjetër; kontrolloni gjithmonë statusin HTTP.

8. Shembull Node.js (Node 20+)

export async function searchFlights(params) {
  const key = process.env.ALBANIA_SKY_API_KEY;
  if (!key) throw new Error("Missing ALBANIA_SKY_API_KEY");
  const response = await fetch(
    "https://albaniasky.com/api/chatbot/v1/flights/search",
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: "Bearer " + key
      },
      body: JSON.stringify(params),
      signal: AbortSignal.timeout(20000)
    }
  );
  const body = await response.json().catch(() => null);
  if (!response.ok) {
    const error = new Error(body?.error?.message || "Flight search failed");
    error.status = response.status;
    error.retryAfter = response.headers.get("retry-after");
    throw error;
  }
  return body;
}

const results = await searchFlights({
  from: "TIA", to: "BGY", departure_date: "2027-01-15",
  adults: 1, children: 0, infants: 0, currency: "EUR"
});

Jepini Claude vetëm rezultatet e nevojshme për përgjigjen, jo çelësin apo headers. Mos shpikni fluturime kur API dështon. Nuk ka endpoint për krijim rezervimesh ose pagesash.
